# Linux candidates and Apple Silicon status

v0.7.0-preview1 includes the registered Scenario 1–3 profiles and the 16:9 menu option. Scenario 3 gameplay and widescreen have not been tested on Linux with real game data.

Download [v0.7.0-preview1](https://github.com/mattkuhnQAAI/sfiii-native/releases/tag/v0.7.0-preview1) for Linux x86-64 desktops. The hosted Apple Silicon runner was unavailable for this release, so no Mac archive is published. Intel Mac packages are no longer published or substituted. Native build, synthetic runtime tests and shader tests do not establish real-disc gameplay compatibility. Check each package's validation report before treating a platform as supported.

## Player workflow

Extract the entire platform archive. On Linux, open the `SFIII Native` executable from the extracted folder; the `.sh` wrapper is also available. On macOS, move `SFIII Native.app` to a local application location and open it. Preview apps are ad-hoc signed, not Apple-notarized; macOS may require explicit approval in Privacy & Security. Do not disable system security globally.

Choose Scenario 1 USA V1.001, Scenario 2 Translation Project v24 or Scenario 3 Translation Project v25.1, select your CUE or standalone CHD, and keep each scenario's game data in a separate writable folder outside the application. Click **Prepare game**, wait, then **Play**. No terminal compilation, Python installation, Homebrew, Xcode or compiler setup is needed for players; Python, Zig's C/C++ toolchain and archive tools, SDL, CMake, Ninja and chdman travel in the package. The hosted Mac toolchain checks passed with Xcode discovery hidden.

Linux initially targets Ubuntu 22.04 or newer desktop environments with their normal X11/Wayland libraries and Vulkan drivers; this is not a promise of every Linux distribution or Steam Deck verification. The source retains its Apple Silicon path, but no build or validation claim is made for it in this release. Vulkan is used on Linux; Metal shaders are generated from the same project-owned shader source for macOS. Hardware and graphics-driver compatibility require testing on actual machines.

Preparation, controller setup/testing, ordinary game saves, BIN/YSBAK save imports, 1×/2×/4×/5× options, experimental widescreen and the native state controls are carried over. For 16:9, use original graphics: AI artwork can misalign or pop in and is not a supported widescreen path. The launcher remembers each scenario's paths. Existing game data is never replaced with test saves. Internal and cartridge memory retain their existing filenames and record format. Back up the data folder before importing or moving progress; use ordinary in-game saves across native builds/platforms. Native snapshots and replay checkpoints require an exact native executable/disc identity.

F5/F9 save and load direct native states. State loading retains exact pre-load internal/cartridge files in the session directory. Legacy replay actions remain separate, and replay progress stays in its own session rather than being copied over live progress automatically. Stop the game before setup or save import; one native file lock prevents concurrent operations against an installation.

## Validation and release status

The hosted Linux job builds the actual bundled-tool candidate without any disc, BIOS, extracted asset, game save or generated game program. It compiles and runs `dsp_regression`, `core_regression`, `bup_regression`, `machine_regression`, `background_regression` and `audio_buffer`, plus synthetic native host/controller/state/UI checks. The Apple Silicon job is unavailable on the current hosted configuration, so it is not treated as passing. The actual SH-2 emitter generates its own synthetic instruction fixture and CMake project; native execution is compared with its recorded instruction vectors. A mixed data/audio CD made from invented sectors is compressed to CHD, verified and extracted with exact sector comparisons; the CHD tool is also checked for unbundled build-machine library dependencies. Shader tests run when the runner exposes a usable GPU; software Vulkan testing is explicitly separate from physical GPU testing. No usable GPU is reported as **unavailable**, never passed.

Real-disc transitions, towns, battles, audio-device behavior and physical controllers on these platforms remain **unavailable validation** until run locally with supplied data and retained seed backups/clock/input. Hosted build results must not be presented as a full-game compatibility result. No game files should be uploaded to hosted jobs or issues. Windows validation and earlier route coverage do not automatically transfer to another OS, CPU, compiler or GPU backend.

Maintainers run `.github/workflows/portable.yml`. Source dependencies and downloaded tool archives are pinned in `desktop/posix-dependencies.json`. Build outputs, caches, native test builds and corresponding MAME source archives stay outside the repository. The generated archives include required notices and the pinned source for the independently invoked CHD converter. The emulator application itself is not packaged.
